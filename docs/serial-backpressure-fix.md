# Serial backpressure repair (source-radio compatibility branch)

The prior writer sampled availableForWrite once and kept serialMutex while writing/flushing every queued record. If initial capacity was zero, sent never advanced. A disconnected/saturated USB consumer could therefore trap the logger while holding the same mutex required by IDF/Wi-Fi log callbacks. Partial write return values were also ignored. This is a reproduced source defect, not proof of the exact device freeze stack.

The writer now retains one pending record and offset, performs one capacity/write attempt per 5 ms tick, uses actual bytes written, never calls flush, and never holds serialMutex across serial I/O. CDC TX timeout is zero from SDK serial initialization (before Wi-Fi setup). Queue producers format into local bounded arrays and attempt the queue mutex with zero wait. Queue capacity is 16 records; when contended/full, new logs are dropped and counted by serial.droppedLogs(). There is no wait/spin for output capacity. Maximum retained text is 17 records of at most 384 bytes including newline, plus Arduino String/queue overhead; transient producer buffers and allocator costs remain. No buffer/priority tuning, task-stack growth, or changes to Wi-Fi/TLS ownership are included. UART implementations and other direct Serial writers are outside a universal nonblocking guarantee.

Preformatted helper, IDF and VFS text now uses explicit %s forwarding, preventing a literal percent sequence from being interpreted a second time. Shared msgbuffer was removed; concurrent producers cannot overwrite another formatted record between unlock and queue insertion. Log API remains variadic/backward-compatible. Logs may be truncated/dropped under backpressure; this is deliberate rather than blocking playback.

Host ASan/UBSan fixtures execute extracted production enqueue/log/err/idf/drainOnce methods: zero output capacity over 10000 ticks, partial/zero writes, reconnect drainage, bounded queue/drops, lock contention, concurrent producers, literal percent data and truncation. Existing source-radio initializer compatibility test passed. Actual ESP32-S3 installed-header syntax-only check passed (existing VFS/header warnings remain); no objects, firmware linking, dependencies or flashing. make clang-format and make cppcheck were attempted but tools are absent; neither gate is claimed passed.

Device acceptance: rebuild LilPlayer using this SDK branch, test rapid stream switches/pause/resume with serial monitor closed, open and disconnected/reconnected. Capture logger task and stack/heap metrics if the freeze remains. LP and SDK are separate serial writers, so complete line interleaving is not solved by this fix; garbled/interleaved lines alone do not prove a lock.
